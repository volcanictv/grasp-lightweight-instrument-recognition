§1 Abstract

This report investigates whether a lightweight convolutional network (MobileNetV3-Small/Large) can achieve competitive surgical instrument recognition on the GraSP dataset (robot-assisted radical prostatectomy video, Ayobi et al. 2024) while using a fraction of the parameters, latency, and memory of heavier architectures. We evaluate four task framings — whole-frame multi-label classification, per-instance region classification, bounding-box detection, and instance segmentation — across frozen and fine-tuned backbones, imbalance-mitigation techniques, a five-model backbone sweep, and a from-scratch anchor-free segmentation architecture.

Fine-tuning is decisive for classification (macro-F1 0.506 to 0.645); reframing whole-frame classification as per-instance region classification resolves the project's worst-performing classes almost entirely (macro-F1 0.825); and a lightweight Faster R-CNN detector reaches mAP@50 = 0.831 while running 3.1x faster than a ResNet-50 variant that is simultaneously less accurate — a clean efficiency-thesis result, not merely a speed/accuracy trade.

Central diagnostic finding

Every detection variant tested loses 25–30 recall points on heavily-occluded instrument instances relative to isolated ones — including an occlusion-targeted copy-paste augmentation that closed the aggregate accuracy gap without moving that number at all. Two follow-up investigations attacked this directly: a lightweight IOU tracker (real recall gain, not yet net-positive on the headline metric) and a from-scratch segmentation architecture (a real capacity bug found and fixed, result still climbing).

A literature check finds every third-party GraSP benchmark uses segmentation metrics (AP50, mcIoU) rather than this project's classification framing; the detection numbers are the first in this project comparable in kind, with a remaining 5–9 point gap on box AP50 and a much larger, only-now-closing gap on the segmentation-specific metrics that are the literature's actual basis for comparison.

§2 Introduction

Surgical instrument recognition matters for workflow analysis, skill assessment, and autonomous assistance. Heavy transformer-based models (TAPIS, the model that ships with the GraSP dataset, is the obvious example) get strong results but come with a real parameter/memory/latency bill — one that's awkward if you actually want this running in an OR in real time. So this project asks a narrower, more useful question: how much of that performance can a lightweight model keep, and how much cheaper does it get? The deliverable here is an honest accuracy/efficiency tradeoff curve, not a new architecture.

GraSP frames routinely contain multiple co-occurring instruments (94.7% of annotated frames contain 2 or more instrument instances), which rules out a single-label whole-frame classification framing as ill-defined. We evaluate four progressively more localization-aware framings:

  • Task A — multi-label frame classification: 7 independent sigmoid outputs per frame, BCE loss, evaluated by mean average precision (AP) and macro-F1.
  • Task B — region classification: each annotated instrument instance is cropped by its bounding box and multiplied by its own segmentation mask, then classified single-label.
  • Detection: Faster R-CNN predicts boxes and classes jointly per frame, evaluated by COCO-style mAP@IoU — the metric family every published GraSP benchmark uses. A lightweight tracking stage was also investigated on top of the best detector.
  • Instance segmentation: an anchor-free architecture predicting per-pixel class and per-instance masks directly, motivated by a diagnosed detection failure mode.

§3 Related work

The GraSP dataset paper (Ayobi et al., "Pixel-Wise Recognition for Holistic Surgical Scene Understanding," arXiv 2401.11174; Medical Image Analysis, 2025) introduces TAPIS, a transformer combining global video features with region proposals from an instrument segmentation model. It reports a single aggregate instance-segmentation metric (mAP@0.5IoU, 89.85%) with no per-class breakdown and no class-balancing technique, despite the same long-tailed distribution this project documents independently.

§4 Methods

4.1Dataset

GraSP: 13 sequences of robot-assisted radical prostatectomy, official split 8 train / 5 test cases, 2324 / 1125 annotated keyframes, 6170 / 2861 instrument instances (7 classes). The distribution is severely long-tailed: Clip Applier has 102 instances total — a 25.6x gap versus Monopolar Curved Scissors (2609). Official case-level splits are used throughout; no custom or frame-level splitting was introduced.

4.2Models

Classification backbones (all torchvision, ImageNet-pretrained): MobileNetV3-Small (proposed), MobileNetV3-Large, EfficientNet-B0, ResNet-18, and ResNet-50 (deliberately heavy baseline). Detection: Faster R-CNN with MobileNetV3-Large-FPN (18.9M params, lightweight default) or ResNet-50-FPN (41.1M params, heavy comparison). Segmentation: a from-scratch, anchor-free architecture combining a semantic head with a centroid-heatmap + offset-regression head, on the same MobileNetV3-Large-FPN family. Two backbone configurations were built — shallow-only feature-pyramid inputs (2.1M params) and a corrected shallow-to-deep span (5.9M params) after the shallow version was found to have a real capacity bug (§4.7).

4.3Training setup

Fine-tuning uses discriminative learning rates (head 1e-3, backbone 1e-4). Task A's best configuration combines inverse-frequency weighted BCE with a stronger augmentation policy, within surgical-plausibility constraints (horizontal flip permitted; no vertical flip, large rotation, or hue shift). Detection trains at full native resolution (1280x800), batch size 4, patience-based early stopping. Tracking-by-detection is a post-processing stage on the best detector, not a trained model — an IOU-Tracker running across densely-sampled raw frames, refined with a confidence gate and a boundary-exit check after an initial version hurt the headline metric (§5). Segmentation targets render at output stride 4 (semantic map, per-class centroid heatmap, offset field); loss is focal (heatmap) + masked L1 (offset) + cross-entropy (semantic), weighted 1.0/0.1/1.0, Adam lr 1e-4, cosine schedule.

4.4Evaluation

Task A: per-class AP, mean AP, macro-F1. Task B: accuracy, macro-F1, per-class PRF, confusion matrix. Detection: mAP@0.5IoU, mAP@[0.5:0.95], per-class AP50 via pycocotools.COCOeval.

Occlusion-stratified recall

Each ground-truth instance is bucketed by the maximum fraction of its box area covered by another co-occurring instrument's box (isolated: 0%, light: ≤50%, heavy: >50%), then recall is measured per bucket at a fixed 0.5/0.5 score/IoU threshold — distinct from the full mAP curve, which needs a much lower score threshold to be a valid precision-recall curve at all.

Segmentation additionally reports Dice, mIoU, AP50_segm, and mcIoU for literature comparability. Instance decoding follows Kurmann et al.'s "mask then classify": foreground pixels group by nearest predicted centroid, then each mask is classified by majority vote from the semantic head.

4.5Hardware & benchmarking

Training and latency benchmarking used 2x NVIDIA Titan Xp (Pascal, no tensor cores, sm_61). Classification models report parameter count, FLOPs/MACs, file size, Titan Xp latency, and ONNX Runtime CPU latency. Detection models report Titan Xp GPU latency only — FLOPs and ONNX export are unreliable for two-stage detectors with a dynamic RPN/ROI pipeline.

§5.6 Tracking-by-detection

Motivated by the ~22ms/frame latency measured above leaving headroom under a 33ms (30fps) real-time budget, and by the occlusion-stratified recall finding above: a cheap post-processing step exploiting temporal continuity, something a purely per-frame detector cannot do at all. Built an IOU-Tracker (Bochinski et al. 2017): greedy box-IoU association between consecutive frames, with track survival through up to max_age missed frames to bridge momentary occlusion.

First check — occlusion-stratified recall (fixed 0.5 threshold): isolated 0.899→0.912–0.913, light 0.920→0.923–0.930, heavy 0.645→0.648–0.683 — a real improvement, verified genuinely causal (real-time-valid).

Second, more demanding check — full mAP@50

The first version of this result scored worse than raw per-frame detection: 0.7899 tracked vs. 0.8264 raw, a ~3.7 point drop. Root cause: coasted (extrapolated) boxes are stale guesses, and two failure modes let a stale box get reported as a confident false positive — low-confidence tracks coasting, and confidently-detected instruments that genuinely left the frame still coasting on a now-wrong box. Fixed with a minimum-confidence gate and a boundary-exit check (a track near a frame edge, moving further outward, is dropped immediately rather than coasted).

A hyperparameter sweep on max_age showed a clean monotonic trend (shorter coasting window, less staleness, less precision loss), with max_age=1 best.

Tried and rejected: occlusion-corridor detection. Extrapolating a missing track's position and checking overlap with another currently-detected instrument, tested in three forms, all underperformed plain max_age=1 (0.8048–0.8089 vs. 0.8130). Most likely explanation: GraSP frames routinely contain 2–3 co-occurring instruments, so "another instrument's box is nearby" is true almost constantly regardless of whether real occlusion is happening.

Honest bottom line

After two real, diagnosed-and-fixed bugs and a hyperparameter sweep, tracking-by-detection's best configuration is still net negative on mAP@50, 1.34 points below the raw detector, despite a real and validated recall benefit at the fixed-threshold diagnostic level. Near-zero added inference cost, sound mechanism, not yet past the bar of improving the headline number.

§5.7 Instance segmentation

Motivated directly by the occlusion diagnosis above: an anchor-free, NMS-free architecture that never suppresses an overlapping instrument's pixels the way box-NMS suppresses a heavily-occluded detection. A semantic head plus a centroid-heatmap + offset-regression head, following Kurmann et al. 2021's "mask then classify" framing, structurally close to Panoptic-DeepLab.

First run and a decode-time bug. The first training run produced a reasonable semantic result (mIoU 0.308) but near-broken instance-level metrics (AP50_segm 0.0017), traced to heatmap-peak decoding defaults copied from COCO-scale conventions — fixed by tuning against real predictions (AP50_segm improved ~38x from the fix alone).

Convergence to a plateau, then a deeper bug. Three further runs (extended patience; cosine LR; copy-paste augmentation) all converged to the same plateau: mIoU 0.309–0.321, AP50_segm 0.098–0.122. Four runs, three interventions, same ceiling — pointing to a capacity problem, not a training one.

The actual cause

The backbone's returned_layers setting, chosen to get a fine-resolution output cheaply, caused torchvision's backbone utility to prune the network before its deep layers were ever computed — not freeze them, remove them from the model entirely. All four plateaued runs were training a model that structurally could not access MobileNetV3-Large's deep semantic features (up to 960 channels), only its shallow, low-capacity early layers (up to 40 channels). Confirmed by direct inspection: the deep backbone layers had zero presence in the training graph.

Fix and current result (running, not final)

A corrected backbone spanning shallow-to-deep feature-pyramid inputs (5.9M total params, still far lighter than the 18.9M-param detector) was built, verified end-to-end (shape checks, a real forward/backward pass confirming gradients reach the deep layers), and launched with the same recipe as the best prior run, plus a second run combining the fix with copy-paste augmentation. As of this writing (epoch 50/44 respectively, both still running, patience=40): plain deep backbone best val mIoU 0.6139 (through epoch 50), copy-paste deep backbone best val mIoU 0.6343 (through epoch 44) — against a ceiling of 0.32 that took 70–100+ epochs to reach under the old configuration. Neither run has patience-stopped, so these are running-best, not final, numbers.

§6 Discussion

6.1Key findings

  1. Fine-tuning a lightweight backbone substantially outperforms using it frozen (macro-F1 0.506 to 0.645).
  2. Combining weighted loss with augmentation compounds gains by addressing distinct failure modes (macro-F1 0.645 to 0.708).
  3. Titan Xp GPU latency does not track parameter count; ONNX CPU latency does.
  4. A heavy classification baseline (ResNet-50) buys a bounded accuracy gain at a steep efficiency cost — a genuine tradeoff curve, not a single dominant point.
  5. Reframing whole-frame classification as region-level classification resolves the project's worst-performing classes almost entirely, using the same lightweight model.
  6. A lightweight Faster R-CNN detector reaches mAP@50 = 0.831 — and more model capacity made this worse, not better, while also being 3.1x slower.
  7. The dominant finding of the detection stage is diagnostic: every variant tried loses ~25–30 recall points on heavily-occluded instances, regardless of backbone, loss, or augmentation.
  8. Tracking-by-detection improves the occlusion-recall diagnostic but is still net negative on mAP@50, even after fixing two real bugs and a hyperparameter sweep. Occlusion-corridor detection, tried in three forms, consistently did not help.
  9. The segmentation architecture's four-run plateau traced to a real, previously undiagnosed capacity bug, not a training or data problem. Fixing it produced an immediate, large improvement (mIoU nearly doubling within a few dozen epochs), though the corrected run has not reached a final number yet.

6.2Comparison to TAPIS and the wider literature

TAPIS reports a single aggregate mAP@0.5IoU_segm of 89.85% with no per-class breakdown. Task A/B's classification numbers remain not directly comparable to that figure. The detection baseline is the first result in this project in the same metric family (AP50) as TAPIS/LACOSTE/QPD, though box-only rather than segmentation-based, and 5–9 points short. A fully legitimate comparison requires the segmentation stage to report a trusted AP50_segm/mcIoU number; the newly-fixed architecture is showing early signs of closing a substantial fraction of that gap, not yet quantified to a final, stable number.

§7 Limitations

  • Task B's result uses ground-truth instance masks; it measures classification accuracy given known localization, not an end-to-end pipeline's accuracy.
  • Rare classes (Clip Applier: 102 total instances; Laparoscopic Grasper: 275) have limited statistical power.
  • Only 13 total surgical cases exist (8 train / 5 test); expect real case-to-case variance not captured by a single split.
  • The occlusion-stratified recall metric is a bbox-overlap proxy, not a measurement of true pixel-level occlusion.
  • All instance-level segmentation metrics compare masks at output-stride resolution (96x96 for a 384 input), not upsampled — understates true mask quality.
  • The corrected segmentation architecture's results were still in progress as of this writing and should be treated as preliminary.
  • No FLOPs/MACs or ONNX-CPU latency for detection or segmentation models (deliberately not attempted for detection).
  • The literature check was a web search, not a systematic review.

§8 Future work

(1) Let the corrected segmentation architecture reach a final, stable number, and re-evaluate its occlusion-stratified recall against the detector now that its capacity bug is fixed. (2) If still short, consider a further capacity increase versus accepting detection + tracking as the project's primary contribution. (3) Milestone 10's inference optimization and final Pareto-style analysis across every model in this report.
